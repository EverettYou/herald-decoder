# Project skills

Skills orchestrate research work; they do not create a benchmark or score references. The intended loop is: acquire a reference, ingest supported knowledge into the shared Wiki, formulate a lab proposal, execute and report the lab, then promote only validated knowledge or reusable code.

`research-workflow` supplies the project-level scientific method across that
loop: orient to the central question, research existing knowledge, build the
physical/mathematical model, register the study, compute or experiment with
provenance, analyze the resulting data, report at the supported claim strength,
and synthesize validated knowledge back into the Wiki. It uses proportional
rigor so routine registered work stays light while claim-bearing studies face
stronger gates.

`auto-research` is the project-wide research-loop coordinator. It identifies the highest-information unresolved question when no remediation contract is active, routes evidence through the Wiki and reusable code through `src/`, runs bounded resumable ticks, and opens a Discussion thread only for a consequential unresolved decision. `consult-human` is the project-wide decision mailbox; it never fabricates a researcher decision.

Multi-part deliverables and correctness remediations use a durable acceptance contract. Per-tick boundedness controls execution size, not whether the overall request remains active. Invalid upstream evidence gates dependent labs, and implementation, branch verification, replacement experiments, analysis, reporting, and visualization remain distinct completion states.
