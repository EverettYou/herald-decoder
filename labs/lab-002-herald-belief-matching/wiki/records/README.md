# Results

> **Active evidence boundary:** every archived artifact carrying
> `weight_rule="negative_log"` has invalid downstream logical fields. Start
> with [`negative-log-invalidation.md`](negative-log-invalidation.md) before
> using any result below. The historical Markdown pages also carry inline
> warnings; raw JSON is provenance, not corrected-decoder evidence.

- `llr-memory-vs-damping-rerun-2026-08-27.json` / `.md` / `.png`: corrected
  posterior-LLR matched $L=5$, $p=0.10$, $q=0.75$ rerun. It compares damping
  with Relay-memory on 300 shared shots per lattice and selects damping: the
  tested Relay-memory configuration is nonconvergent, slower, and has no LER
  improvement.
- `llr-systematic-memory-vs-damping-rerun-2026-08-27.json` / `.md` / `.png`:
  corrected posterior-LLR six-cell replication (1000 matched shots/cell) on
  lattice-specific observable-error grids. Relay-memory significantly
  regresses at square $p=0.08$, has no resolved benefit elsewhere, worsens
  proper scores throughout, and never converges; damping is selected for
  Lab 003.
- `convergence-ablations-c1.json` / `../figures/convergence-ablations-c1.png`:
  complete 64-observation matched study of damping, update schedule, and
  initialization. Residual-priority Gauss--Seidel scheduling raises the
  fixed-point rate from 18.8% to 34.4% without a detected log-loss regression;
  it remains an experimental recurrence candidate, not a promoted decoder.
- `residual-priority-c2.json` / `../figures/residual-priority-c2.png`:
  64-shot end-to-end posterior-LLR validation of that candidate. Every
  correction is syndrome faithful and convergence improves, but the Python
  implementation is 243.6 ms slower per observation after timing controls;
  C3 must compile and revalidate it before any promotion.
- `residual-priority-c3.json` / `residual-priority-c3-honeycomb.json` /
  `../figures/residual-priority-c3.png`: compiled residual-priority schedule
  is bit-identical to the Python experiment on 64 square and 8 honeycomb
  fixed observations. The square timing difference from synchronous Numba is
  unresolved; an independent multi-geometry replication remains required.
- `residual-priority-c4.json` / `../figures/residual-priority-c4.png`: fresh
  square and honeycomb compiled replication. Square convergence improves by
  15.6 points but costs 2.08 ms per observation; honeycomb has no convergence
  headroom but needs fewer iterations. C5 profiles the scheduling overhead.
- `residual-priority-c5.json` / `../figures/residual-priority-c5.png`: exact
  64-observation compiled equivalence test of repeated maximum scanning and
  stable residual sorting. Sorting reduces mean inference time from 9.62 ms
  to 7.61 ms (paired difference -2.01 ms, 95% interval [-4.27, -0.29]) while
  preserving every checked output. A common-protocol synchronous comparison
  remains required before promotion.
- `residual-priority-c6.json` / `../figures/residual-priority-c6.png`: fresh
  common-protocol square/honeycomb comparison of synchronous Numba and
  stable-sort residual priority. Square convergence improves by 15.6 points,
  but end-to-end decode remains slower by 1.63 ms; honeycomb remains slower by
  0.29 ms. Every correction is syndrome faithful and logical counts are tied.
- `residual-priority-c7.json` / `../figures/residual-priority-c7.png`: exact
  C6-stream equivalence test of preallocated iteration buffers. Outputs are
  bit-identical, but buffer reuse is slower by 0.85 ms on square and 0.053 ms
  on honeycomb, so it remains disabled by default.
- `residual-priority-c8.json` / `../figures/residual-priority-c8.png`:
  cached-product numerical-equivalence gate. It fails on 13 square and 15
  honeycomb observations, including one square correction disagreement and
  three honeycomb iteration disagreements, so timing is skipped and the
  candidate is rejected.

- `bp-optimization-validation.json` / `.md`: frozen-executable equivalence checks, inherited Numba runtime, before/after timing, and parallel wall time.
- `relay-transfer-mechanism.json` / `.md`: mechanism-only audit contrasting hard syndrome validity, numerical fixed points, and the observation-only proxy across Relay legs.
- `relay-selection-ablation.json` / `.md`: matched 1000-shot soft-output ablation of proxy, first-leg, and hard-validity-restricted Relay leg selection rules.
